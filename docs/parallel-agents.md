# Parallel Multi-Agent Formalization Workflow (`compose` + `campaign`)

Large protocol specifications exceed single-prompt context limits and single-module Lean elaboration budgets. `Formal-Spec-Agent` separates **declarative protocol composition** (`compose`), **parallel sharded proof orchestration** (`campaign`), and **final deterministic pipeline integration** (`run` / `verify`).

## Trust & Agent-Agnostic Contract

- **Files + CLI interface**: any external agent harness (Antigravity subagents/swarm, Gemini, Codex, Claude Code, or custom scripts) uses the exact same `campaign` CLI (`claim` / `submit` / `release` / `status`), OR delegates directly via `campaign run-workers`.
- **Single source of truth**: `Approved.lean` and `model.json` are generated by the trusted controller and locked (`0444`). Workers cannot mutate `model.json`, `Approved.lean`, invariants, or `campaign.json`.
- **Trusted kernel gatekeeper**: every candidate `<Module>.lean` submitted by any worker is statically screened (`sorry`, `admit`, `axiom`, `unsafe`, `extern`, `#eval`, disallowed imports), compiled against precompiled `.olean`s in an isolated directory under Lean 4.35.0, and audited with `#print axioms Audit_<Module>.check_<goal>` before admission.

## Step 1: Compose Protocols from Modular Component Specs (`compose`)

Author small, focused IR component files (for example `components/part_a.json`, `components/part_b.json`) inside a workspace and declare a pinned `fsa-compose-v1` recipe:

```sh
formal-spec-agent compose /path/to/ws/compose.json \
  --workspace /path/to/ws \
  --out /path/to/ws/model.json \
  --receipt /tmp/compose-receipt.json
```

Each component can specify an optional namespace `prefix` so shared variable/event/timer/message names never collide unless intentionally shared across components (conflicting declarations with differing values/types are rejected).

## Step 2: Initialize and Precompile a Sharded Proof Campaign (`campaign init`)

Using `examples/lean-timed-efsm` (or any target protocol workspace) as an example:

```sh
formal-spec-agent campaign init \
  --workspace examples/lean-timed-efsm \
  --model examples/lean-timed-efsm/model.json \
  --campaign /tmp/timed-campaign \
  --lean "$FSA_LEAN" \
  --shard-size 2 \
  --cache-dir /tmp/shared-lean-cache
```

This renders `Approved.lean`, precompiles the 32 core framework modules + `Approved.lean` once into `<campaign>/olean_cache/`, and splits all goals into independent, mutually non-interfering shards:
- `core_contracts` (`CoreContracts.lean`)
- `conflict_shard_000 .. N` (`ConflictShardNNN.lean`)
- `firing_shard_000 .. M` (`FiringShardNNN.lean`)

Every shard carries a deterministic `cache_key`; unchanged shards across protocol edits can be reused only after re-verifying against the current `Approved.olean`.

## Step 3: Execute Workers in Parallel

### Option A: External agents (`claim` / `submit` / `release`)

Each worker runs independently in its own context:

```sh
# 1. Lease next ready shard under POSIX flock (writes brief + skeleton_lean)
formal-spec-agent campaign claim --campaign /tmp/timed-campaign --worker agent-1

# 2. Worker writes staging Lean file, then submits to trusted Lean 4.35.0 checker
formal-spec-agent campaign submit --campaign /tmp/timed-campaign \
  --unit firing_shard_000 --worker agent-1 \
  --source /tmp/timed-campaign/staging/firing_shard_000-agent-1.lean --lean "$FSA_LEAN"
```

Failed Lean attempts record structured diagnostics (`last_error` and `<campaign>/attempts/*.stderr`) so the next claim immediately sees why elaboration failed. Expired leases are automatically reclaimed.

### Option B: Built-in Parallel Controller (`run-workers`)

Drive either arbitrary worker CLI templates (`--backend command`) or ledgered LLM providers (`--backend provider --provider gemini`):

```sh
formal-spec-agent campaign run-workers \
  --campaign /tmp/timed-campaign --lean "$FSA_LEAN" \
  --concurrency 4 --backend command \
  --cmd "my-agent-wrapper --brief {brief} --out {out}"
```

## Step 4: Assemble, Emit C99, and Run Complete Verification (`assemble`)

Once `status` reports `ready_to_assemble: true`, assemble synthesizes `TimedProof.lean` (combining all verified shards via `each_append`), generates a paired `fsa-lean-timed-proof-manifest-v2` (`compile_groups`), optionally updates `flow.json` source digests (`--update-flow`), and runs the 10-stage `run` + `verify` pipeline (`--run-flow`) yielding standalone C99 `protocol.c` + complete evidence:

```sh
formal-spec-agent campaign assemble \
  --campaign /tmp/timed-campaign \
  --out-workspace /path/to/out-ws \
  --update-flow flow.json --run-flow \
  --flow-out /tmp/timed-flow --lean "$FSA_LEAN"
```

See [examples/lean-timed-efsm/README.md](../examples/lean-timed-efsm/README.md) and [tests/test_campaign.py](../tests/test_campaign.py) for end-to-end sharded proof + assembly usage.
